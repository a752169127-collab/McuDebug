MCU Debug Assistant

一个基于 Python + PySide6 + pyqtgraph + SEGGER J-Link DLL 的 MCU 调试工具，目标体验接近 Keil Watch + J-Scope + AXF Symbol Browser，并作为后续算法回溯、死机分析、自动化调试平台的底座。

Read / Write
JLINK_ReadMemEx / WriteMemEx
HSS / RTT
Scope 高速采样
AXF / DWARF
自动符号与成员解析
核心定位：Watch 负责低速、可写、统计；Scope 负责高速波形；AXF 消除手工地址录入；JLinkWorker 统一持有 J-Link Session。

2. 总体架构

        ▼

  ├─ Visible Window
  ├─ Downsample
  ├─ Gain / Offset
  └─ Cursor / Probe
        │
        ▼
JLinkWorker (唯一 J-Link Owner)
  ├─ Connect / Disconnect
  ├─ ReadMemEx / WriteMemEx
  ├─ HSS
  └─ RTT
        │
        ▼
JLink_x64.dll → MCU

另一条关键链路：

AXF / ELF / DWARF → Symbol Model → Watch / Scope Channel Definition
不可破坏：GUI、Watch、Scope 都不能直接抢 J-Link DLL；所有访问必须统一经过 JLinkWorker。

4. Watch 设计

性能模型

J-Link Sampling: 100 / 500 / 1000 Hz
Statistics: 每个真实采样点参与
GUI: 约 25 Hz Snapshot

Sampling Rate != GUI Refresh Rate

20+变量早期卡顿来自逐单元格高频刷新；通过 Worker 在线统计、Snapshot 批量更新、关闭动态 ResizeToContents、row_id 映射解决。

平均值复制

复制到剪贴板只保留数值，用 TAB 分隔，直接粘贴 Excel 一行；不弹窗，只写 Log。

5. AXF / ELF / DWARF

AXF → ELF Symbol Table → DWARF → Struct / Array / Member → Symbol Browser → Watch / Scope

ARMCC5 DWARF3 关键兼容

BlowerParamsObj = 0x20002894
m_PosSpeed      offset 132 → 0x20002918
m_Position      offset 136 → 0x2000291C

Keil ARMCC5 的 DW_AT_data_member_location 使用 DW_FORM_block + DW_OP_plus_uconst。旧解析器只认 constant/exprloc，导致结构体成员被漏掉；后续增加 ARMCC5 DWARF2/3 专用成员偏移解析。

Symbol Search

从“每输入一个字符重建 QTableWidget”改成 QStandardItemModel + QSortFilterProxyModel + QTreeView，并加 debounce，搜索不卡。

Reload Rebind

重新解析 AXF → 按完整 Name 匹配 → 更新 Address/Type → 不存在则删除 → 清旧统计

6. Scope 设计

HSS Timestamp

[Timestamp U32][Payload...]
Timestamp → X
Payload   → int16 / uint32 / float ... → Y

最早固定 1000 的变量画成递增/三角波，根因就是把 Timestamp 当成数据。

Raw / Display 分离

Raw Buffer
 ├─ Statistics
 ├─ CSV
 ├─ Cursor / Probe
 └─ Display Pipeline
      ↓ Visible Window
      ↓ Peak-Preserve Downsample
      ↓ Gain / Offset
      ↓ PlotCurveItem

Show / Start / Pause / Follow

操作语义
Show只隐藏/显示，继续采样，历史保留
Start新实验：清旧 Buffer / Statistics，再开始
Pause停采样但保留当前分析现场
Follow只移动 X，不自动改 Y

Gain / Offset

Y_display = Y_raw × Gain + Offset
+ / -         调 Gain
Ctrl + / -    调 Offset

History / Analyze

Follow OFF 时，右侧新数据继续进入 Raw Buffer 和 Statistics，但当前历史窗口不重复 setData；用户拖动/缩放后才重画新窗口。

Interaction Mode / Cache

拖动期间冻结 Curve setData、Hover、表格刷新等非必要 GUI 工作，只保留 ViewBox Transform；HSS/RTT、Raw Buffer、Statistics 继续。松手后按最终 XRange 精确重画。

8. 问题 → 根因 → 解决

固定值变递增三角波

HSS Timestamp 被当数据 → Timestamp/Payload 分离。

20+ Watch 卡

逐Cell高频刷新 → Worker统计 + Snapshot + GUI限频。

AXF 搜索输入一个字母就卡

每键重建表 → Model/View + ProxyFilter。

结构体成员解析不到

ARMCC5 DW_FORM_block + DW_OP_plus_uconst → 增加 DWARF3 成员偏移解析。

Scope 越跑越卡

每批 np.concatenate 全历史 → Chunked Buffer。

X轴放大后“点变少”

先全局降采样再局部显示 → 先 Visible Window，再 Peak-Preserve Downsample。

Stacked + Follow 手感不够丝滑

多 Plot/ViewBox/Scene 和 pyqtgraph 更新成本高。已做 Follow限频、Render Clock、History/Interaction Mode、Interaction Cache，但仍未达到 J-Scope。

Requested 1000 Hz → Actual ~496~499 Hz

更像 HSS/J-Link 实际吞吐限制，需要独立做 J-Link 型号、SWD速度、变量数量/宽度、HSS period、DLL版本基准。

9. 不可破坏的设计原则

  1. GUI不直接访问J-Link。
  2. Sampling 与 GUI FPS 分离。
  3. Raw 与 Display 分离。
  4. Gain/Offset只影响显示。
  5. Show不影响采集/Buffer。
  6. Pause不清数据，Start才清旧实验。
  7. AXF Reload必须重绑地址。
  8. Symbol Search不能每键重建UI。
  9. 长缓存不能反复整段 concatenate。
  10. 先裁Visible Window，再Downsample。
  11. Downsample保峰谷。
  12. 拖动期间暂停非必要GUI任务。
  13. Follow只动X不动Y。
  14. Actual Hz必须独立测量。

11. 新人接手路线

  1. 先读 JLinkWorker：谁持有 Session，谁能访问 DLL。
  2. 再读 Symbol Model：AXF 如何生成 Watch/Scope channel。
  3. 再读 Watch：理解 Sampling 与 GUI Snapshot 解耦。
  4. 最后读 Scope：Raw Buffer → Statistics → Display Pipeline → ViewBox。
  5. 遇到卡顿先计时定位，不要凭感觉乱改：HSS Read、Buffer append、Visible Slice、Downsample、setData、ViewBox、Table refresh。
新人只要掌握两条链：
JLinkWorker → Acquisition → Raw Buffer → Statistics / Display → Watch / Scope
AXF → Symbol Model → Watch / Scope Channel Definition
